## Context

Канбан-доска состоит из колонок, каждая из которых содержит список карточек. В текущей реализации в заголовке колонки отображается только название. Данные о карточках передаются в компонент колонки через props в виде массива.

## Goals / Non-Goals

**Goals:**
- Добавить отображение числа карточек в заголовке каждой колонки
- Счётчик должен обновляться автоматически при изменении содержимого колонки

**Non-Goals:**
- Фильтрация или группировка карточек в счётчике
- Изменение архитектуры хранения состояния
- Добавление счётчиков в другие области интерфейса (хедер, список колонок)

## Decisions

### Решение 1: Источник данных для счётчика

**Выбор:** Счётчик вычисляется из длины массива карточек, передаваемого в компонент колонки через props.

**Почему так:**
- Данные о карточках уже доступны в родительском компоненте (доске)
- Избегаем дублирования состояния и рассинхронизации
- Не требуется дополнительных хуков или сторов — счётчик является производным значением

**Альтернативы:**
- Передавать готовое число из родителя — проще, но менее гибок при расширении
- Вычислять счётчик внутри колонки через отдельный стор — избыточно для текущей задачи

### Решение 2: Визуальное оформление

**Выбор:** Счётчик отображается в виде числа в круге (badge) с использованием CSS-модуля колонки.

**Почему так:**
- Badge-паттерн стандартен для отображения счётчиков
- Легко читается, визуально отделён от названия
- Не требует внешних библиотек или иконок

**Альтернативы:**
- Просто число без оформления — менее заметно
- Иконка с текстом — избыточно для простой задачи

## Risks / Trade-offs

| Risk | Mitigation |
|------|------------|
| При переходе на реальный сервер счётчик может потребовать пересчёта на бэкенде | Сейчас счётчик — чисто клиентское отображение, бэкенд может возвращать count отдельно, если потребуется |
| При большом количестве колонок счётчик может сливаться с соседними | CSS-стили обеспечивают достаточный отступ и контраст |
