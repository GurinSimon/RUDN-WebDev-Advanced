## Как устроены семинары курса

На этом курсе ты ведёшь **один проект — канбан-доску** — от первого семинара до последнего. Каждая тема добавляет к проекту новый слой: сегодня — клиент на React, дальше — сервер, база данных, авторизация. Проект живёт в твоём Git-репозитории весь семестр, и работа с ним ведётся так, как принято в командной разработке: ветка на задачу, осмысленные коммиты, pull request.

Каждый семинар состоит из **трёх заданий**:

- **Задания 1 и 2 — промежуточные.** Они небольшие и намеренно простые: каждое тренирует один конкретный навык, без которого не выполнить третье. Они не оцениваются в баллах, но выполняются обязательно — оценочное задание строится на их результате.
- **Задание 3 — оценочное.** Оформлено как рабочий тикет — задача в том виде, в каком её получает джуниор-разработчик в команде: описание, критерии приёмки, сдача через pull request.

## Задание 1 (промежуточное). Каркас доски: компоненты и рендеринг

**Навык:** компоненты, типизация props, условный и циклический рендеринг, CSS-модули.
**Навык Git:** форк и клонирование, ветка на задачу, атомарные коммиты.

Разверни стартовый проект и собери статичный каркас доски:

1. Компонент `BoardCard`: принимает `title: string`, `isDone: boolean` и необязательный `isUrgent`. У срочной невыполненной карточки — бейдж «Срочно»; выполненная отображается приглушённо (полупрозрачность, зачёркивание). Тип props опиши отдельным `type BoardCardProps`.
2. Компонент `BoardColumn`: принимает массив карточек и отрисовывает их через `.map()`; если массив пуст — текст «Колонка пуста». Данные пока захардкоженный массив в родительском компоненте.
3. Все стили — через CSS-модули (`*.module.css`), без глобальных классов и инлайн-стилей.

Порядок работы с Git — с этого задания и навсегда:

```bash
git switch -c feature/board-skeleton   # ветка на задачу, main не трогаем
# ... работа, по коммиту на осмысленный шаг:
git commit -m "feat: add BoardCard component"
git commit -m "feat: add BoardColumn with empty state"
git push -u origin feature/board-skeleton
```

> [!IMPORTANT]
> Коммит описывает изменение, а не твоё состояние: `feat: add BoardCard component` — да, `fix2` и `сделал всё` — нет. Привычка коммитить мелкими осмысленными шагами — часть навыка, который здесь тренируется.

**Проверь себя:** `key` у элементов списка — стабильный `id` из данных, а не индекс массива; проект собирается без ошибок TypeScript (`npm run build`); история коммитов читается как список шагов.

## Задание 2 (промежуточное). Живая доска: хуки

**Навык:** `useState`, `useRef`, `useEffect` — по одному конкретному применению каждого.
**Навык Git:** влить предыдущую ветку в `main`, начать новую от актуального `main`.

Сначала Git: открой pull request из `feature/board-skeleton` в `main` своего репозитория, просмотри свой diff глазами (это и есть self-review), влей его. Новую ветку `feature/board-interactivity` создавай уже от обновлённого `main`.

Теперь оживи доску:

1. **`useState`.** Форма над колонкой: поле ввода и кнопка «Добавить». Текст поля — контролируемое состояние; по кнопке карточка добавляется в список (список тоже переезжает в `useState`), поле очищается. Кнопка недоступна при пустом поле. Массив обновляется иммутабельно: `[...cards, newCard]`.
2. **`useRef`.** После добавления карточки фокус возвращается в поле ввода. Подумай и ответь себе: почему здесь `useRef`, а не `useState`?
3. **`useEffect`.** Заголовок вкладки показывает число невыполненных карточек: `Доска (3)` — и обновляется при изменении списка.

**Проверь себя:** в консоли браузера нет предупреждений React; у `useEffect` правильный массив зависимостей; ветка запушена и влита в `main` через PR.

## Задание 3 (оценочное). Тикет: доска с сервером и фильтром

Это задание оформлено как задача из трекера — читай его как тикет, который тебе назначили.

> **KAN-1: Подключить доску к серверу и добавить фильтр выполненных**
>
> Сейчас карточки живут в памяти вкладки и пропадают при перезагрузке. Нужно перевести доску на серверные данные и дать пользователю возможность скрывать выполненные карточки.
>
> **Критерии приёмки:**
>
> 1. Список карточек загружается с сервера через React Query (`useQuery`, ключ `["cards"]`); локального `useState` со списком больше нет;
> 2. Пока данные грузятся, виден индикатор загрузки; при ошибке — сообщение об ошибке, а не пустой экран;
> 3. Создание карточки идёт через `useMutation` (POST); после успеха список обновляется через инвалидацию кэша, кнопка на время запроса заблокирована;
> 4. В шапке — переключатель «Скрыть выполненные»; его значение живёт в сторе Zustand, колонка читает его через селектор и фильтрует карточки при отображении;
> 5. Отфильтрованный список нигде не хранится — вычисляется в компоненте из данных `useQuery` и значения фильтра;
> 6. `npm run build` проходит без ошибок, в консоли нет предупреждений React.

## Частые ошибки — проверь себя перед сдачей

- Индекс массива в `key` — при удалении карточек состояние «переедет» между ними;
- Список карточек одновременно в `useState` и в кэше React Query — два источника истины;
- Обновление интерфейса после мутации вручную вместо `invalidateQueries`;
- Подписка на весь стор Zustand без селектора — лишние перерисовки;
- Работа в `main` напрямую и один коммит «всё сразу» — Git-часть задания не засчитывается.
